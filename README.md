# FinSight — финансовая аналитика

FinSight — веб-приложение для работы с финансовыми транзакциями и просмотра аналитики. Проект состоит из backend на Node.js/Express и frontend на React. Для обновления интерфейсов в реальном времени используется Socket.IO.

## Технологии

**Backend:** Node.js, Express, Socket.IO, Sequelize, PostgreSQL, JWT, Nodemailer.

**Frontend:** React, Vite, Socket.IO Client, Axios, Recharts.

## Установка и запуск

### 1. Backend

Откройте PowerShell и перейдите в каталог backend:

```powershell
cd C:\financial-analytics-api\backend
npm install
```

Создайте локальный файл `backend/.env` и заполните параметры подключения к PostgreSQL, секрет JWT и настройки почтового сервиса, если используются функции электронной почты. Используйте имена переменных, предусмотренные конфигурацией backend вашего проекта.

Запустите сервер:

```powershell
npm run dev
```

Backend в локальной конфигурации доступен по адресу `http://localhost:3000`.

### 2. Frontend

Откройте второе окно PowerShell:

```powershell
cd C:\financial-analytics-api\frontend
npm install
npm run dev
```

Vite обычно запускает приложение по адресу `http://localhost:5173`.

Если frontend использует локальные переменные окружения, настройте `frontend/.env` в соответствии с адресом API в исходном коде.

Для работы приложения должны быть запущены PostgreSQL, backend и frontend.

## Переменные окружения и безопасность

Файлы `.env` содержат локальные настройки и секреты. Они должны оставаться на компьютере разработчика и не должны попадать в публичный репозиторий.

Проверьте, что backend подключается к нужной базе PostgreSQL и что задан JWT-секрет. При использовании восстановления пароля должны быть настроены параметры почтового сервиса.

Не публикуйте пароли, JWT-секреты, SMTP-пароли и другие учётные данные в README или GitHub. Не помещайте секретные ключи во frontend: данные, переданные браузеру, доступны пользователю.

## Работа Socket.IO

В FinSight Socket.IO используется для уведомлений и синхронизации финансового интерфейса между подключёнными клиентами.

1. Пользователь открывает React-приложение и проходит авторизацию.
2. Socket.IO Client устанавливает соединение с backend и передаёт JWT-токен в параметре `auth`.
3. Сервер проверяет JWT. При успешной проверке разрешает подключение.
4. Пользователь присоединяется к комнате `financial-space`.
5. Сервер передаёт клиентам события о присутствии пользователей и системные уведомления.
6. После создания, изменения или удаления транзакции сервер рассылает соответствующее событие.
7. Клиенты, получившие событие, повторно запрашивают актуальные транзакции через REST API. Источником финансовых данных остаётся PostgreSQL.

### Используемые события

| Событие | Направление | Назначение |
|---|---|---|
| `connection` | Серверное | Обработка нового Socket.IO-подключения |
| `disconnect` | Серверное | Обработка отключения клиента |
| `presence:updated` | Сервер → клиенты комнаты | Передача списка пользователей онлайн |
| `system:notification` | Сервер → клиенты комнаты | Системные уведомления |
| `transaction:created` | Сервер → клиенты комнаты | Уведомление о создании транзакции |
| `transaction:updated` | Сервер → клиенты комнаты | Уведомление об изменении транзакции |
| `transaction:deleted` | Сервер → клиенты комнаты | Уведомление об удалении транзакции |
| `financial:refresh` | Клиент → сервер | Запрос синхронизации с acknowledgement |
| `ping` | Клиент → сервер | Проверка доступности соединения |

### Дополнительные механизмы

- **Комната `financial-space`:** объединяет авторизованных пользователей общего финансового пространства.
- **JWT-авторизация:** сервер проверяет токен до допуска клиента к событиям.
- **Присутствие пользователей:** сервер поддерживает список подключённых пользователей и обновляет его при изменении соединений.
- **Системные уведомления:** клиенты получают информацию о подключении и отключении пользователей и запросах синхронизации.
- **Синхронизация транзакций:** Socket.IO сообщает об изменении данных, после чего клиент получает актуальные данные через REST API.
- **Acknowledgement:** сервер возвращает клиенту результат обработки `financial:refresh`.
- **Повторное подключение:** Socket.IO Client настроен на попытки восстановления соединения.
- **Ограничение частоты запросов:** сервер ограничивает частоту обработки запросов синхронизации.

## Проверка функций реального времени

Для демонстрации откройте приложение в двух окнах браузера и авторизуйтесь.

1. Убедитесь, что в обоих окнах отображается состояние подключения.
2. Проверьте отображение пользователей онлайн.
3. Откройте второе окно и проверьте появление уведомления о подключении.
4. Создайте или измените транзакцию в одном окне.
5. Убедитесь, что второе окно получает событие об изменении и обновляет список транзакций.
6. Проверьте ручной запрос синхронизации и получение подтверждения от сервера.
7. Закройте одно из окон и проверьте обновление присутствия и уведомление об отключении.
